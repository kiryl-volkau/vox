# Контекст проекта vox

Этот файл читает сам vox: клиент отправляет его вместе с записью, и он попадает в системный
промпт как контекст репозитория. Он нужен, чтобы модель правильно писала имена из этого проекта
и понимала, о чём идёт речь, когда задача диктуется вслух. Держи его коротким и фактическим.

## Что это за проект

vox — голосовой ввод для Claude Code на Windows 11. Речь записывается, распознаётся Whisper на
GPU, затем локальная LLM превращает расшифровку в формализованную постановку задачи. Текст
попадает в терминал IDE или в буфер обмена; Enter никогда не нажимается автоматически.

## Части и их имена

- `src/vox_server` — backend на FastAPI в Docker (Linux, CUDA). Модули: `api`, `processor`,
  `transcription`, `llm`, `prompt`, `glossary`, `config`, `health`, `trace`, `main`.
- `src/vox_client` — нативный Windows-компаньон (push-to-talk, микрофон, overlay, буфер обмена).
  Модули: `main`, `hotkeys`, `state`, `recorder`, `clipboard`, `overlay`, `project`, `api_client`,
  `config`.
- `plugin` — плагин IntelliJ IDEA на Kotlin, пакет `dev.vox.idea`. Основные классы:
  `VoxDictationService`, `VoxClient`, `VoxSettings`, `VoxConfigurable`, `TerminalInserter`,
  `AudioRecorder`, `AudioDevices`, `ProjectContext`, `ClaudeCodeContext`, `VoxTranscriptStore`,
  `VoxWorkbenchPanel`, `VoxLanguages`, `VoxStatusWidget`, `DictateAction`,
  `EditProjectContextAction`, `OpenWorkbenchAction`.
- `prompt.md` и `dictation.md` — промпты: секции `## SYSTEM`, `## USER` и `## LANGUAGE <код>`,
  плейсхолдеры `{instructions}`, `{project}`, `{context}`, `{language}`, `{glossary}`,
  `{transcript}`.
- `config/glossary.yaml` — словарь «разговорная форма -> канонический термин». Значение — либо
  строка (одно написание на все языки), либо мапа `ru`/`en`. Он же даёт Whisper hotwords.
- `config/client.yaml` — конфигурация компаньона.
- `traces/` — JSON-трейсы запросов, включаются через `VOX_TRACE_DIR`.
- `src/vox_server/runtime_config.py` — override настроек LLM в `/state`, победитель над `.env`.

## HTTP-контракт

`POST /v1/process` (multipart: `audio`, плюс `project`, `project_name`, `context`, `language`,
`client_id`, `client_version`, `audio_seconds`), `POST /v1/dictate` (те же поля),
`POST /v1/transcribe`, `POST /v1/transform`, `GET /health`, `GET`/`PUT /v1/config`
(настройки LLM на лету; они переживают перезапуск и важнее `.env`). Какой промпт сработает, решает путь, а
не тело запроса. `language` — это язык ответа; язык речи задаётся отдельно через `STT_LANGUAGE`.
`context` — последние реплики сессии Claude Code, которые прислал клиент.

## Стек

Python 3.14, uv, FastAPI, pydantic-settings, faster-whisper 1.2 на CTranslate2 + CUDA,
OpenAI-совместимая LLM (Ollama, по умолчанию `qwen2.5:7b-instruct`). Kotlin и IntelliJ Platform
Gradle Plugin для плагина. Тесты — pytest (`uv run pytest`), линт — ruff, типы — mypy в strict.

## Ограничения, которые нельзя нарушать

- Телеметрии и базы данных нет, аудио с машины не уходит никогда.
- LLM по умолчанию локальная, но `LLM_BASE_URL` можно направить на чужой endpoint. Тогда
  расшифровка, `.vox.md` и контекст беседы уходят туда — это осознанный выбор владельца
  установки, а не то, что код решает сам. Код обязан оставлять этот выбор за ним: не
  зашивать адрес, не слать ничего сверх того, что нужно запросу.
- Аудио никогда не пишется на диск.
- Backend не читает репозиторий: клиент присылает ровно один файл — этот.
- Enter за пользователя не нажимается: текст всегда остаётся на проверку.
- Трейсы содержат расшифровки и промпты, поэтому по умолчанию выключены.
