# vox project context

vox reads this file itself: the client sends it with the recording and it lands in the system
prompt as the repository's context. It is here so the model spells this project's names correctly
and understands what is being talked about when a task is dictated aloud. Keep it short and
factual.

## What this project is

vox is voice input for Claude Code on Windows 11. Speech is recorded, recognised by Whisper on the
GPU, and a local LLM then turns the transcript into a formalised task statement. The text lands in
the IDE terminal or on the clipboard; Enter is never pressed automatically.

## The parts and their names

- `src/vox_server` - the FastAPI backend in Docker (Linux, CUDA). Modules: `api`, `processor`,
  `transcription`, `llm`, `prompt`, `analysis`, `glossary`, `config`, `health`, `trace`, `main`.
- `plugin` - the IntelliJ IDEA plugin in Kotlin, package `dev.vox.idea`. Main classes:
  `VoxDictationService`, `VoxClient`, `VoxSettings`, `VoxConfigurable`, `TerminalInserter`,
  `AudioRecorder`, `AudioDevices`, `ProjectContext`, `ClaudeCodeContext`, `VoxTranscriptStore`,
  `VoxWorkbenchPanel`, `VoxLanguages`, `VoxStatusWidget`, `DictateAction`,
  `EditProjectContextAction`, `OpenWorkbenchAction`.
- `prompt.md`, `dictation.md` and `analysis.md` - the prompts: sections `## SYSTEM`, `## USER` and
  `## LANGUAGE <code>`, placeholders `{instructions}`, `{project}`, `{context}`, `{language}`,
  `{glossary}`, `{transcript}`, `{output}`.
- `config/glossary.yaml` - the "spoken form -> canonical term" dictionary. A value is either a
  string (one spelling for every language) or a `ru`/`en` map. It also supplies Whisper hotwords.
- `traces/` - JSON request traces, switched on through `VOX_TRACE_DIR`.
- `src/vox_server/runtime_config.py` - the LLM settings override in `/state`, which outranks `.env`.

## The HTTP contract

`POST /v1/process` (multipart: `audio`, plus `project`, `project_name`, `context`, `language`,
`client_id`, `client_version`, `audio_seconds`), `POST /v1/dictate` (the same fields),
`POST /v1/transcribe`, `POST /v1/transform`, `GET /health`, `GET`/`PUT /v1/config` (LLM settings at
runtime; they survive a restart and outrank `.env`). Which prompt runs is decided by the path, not
by the request body. `language` is the language of the answer; the spoken language is set
separately through `STT_LANGUAGE`. `context` is the most recent Claude Code exchange the client
sent. Responses from `/v1/process` and `/v1/transform` also carry `analysis`, the second pass's
report of how the speech was read, which is null whenever that pass could not answer.

## The stack

Python 3.14, uv, FastAPI, pydantic-settings, faster-whisper 1.2 on CTranslate2 + CUDA, an
OpenAI-compatible LLM (Ollama, `qwen2.5:7b-instruct` by default). Kotlin and the IntelliJ Platform
Gradle Plugin for the plugin. Tests are pytest (`uv run pytest`), linting is ruff, typing is mypy
in strict mode.

## Constraints that must not be broken

- There is no telemetry and no database, and audio never leaves the machine.
- The LLM is local by default, but `LLM_BASE_URL` can be pointed at somebody else's endpoint. The
  transcript, `.vox.md` and the conversation context then go there - a deliberate choice by whoever
  owns the installation, not something the code decides on its own. The code has to leave that
  choice with them: never hard-code the address, never send more than the request needs.
- Audio is never written to disk.
- The backend does not read the repository: the client sends exactly one file, this one.
- Enter is never pressed on the user's behalf: the text is always left for review.
- Traces hold transcripts and prompts, so they are off by default.
